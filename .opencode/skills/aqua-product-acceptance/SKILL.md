Read docs/design-system/product-acceptance.md and the task packet. Reconcile
conflicting old requirements before editing; DESIGN.md's dated precedence
applies. Keep context bounded to the affected journey and shared consumers.

Before implementation state the actor, intended outcome, information owners,
default versus detailed copy, device-specific layout, scroll ownership, required
states, exclusive files and intended RED. Preserve security/money/consent/offline
and parent zero-JS contracts. Do not invent missing product capabilities.

Meaning, function and appearance need separate acceptance. In particular reject
attendance inside Money, duplicate neighbouring scope/comparison sentences,
misleading paid/healthy/delivered claims and oversized empty comparison frames.
Check exact range/drill-down parity and unknown attendance. Phone/desktop may
have different grids, icon sizes and density while preserving behaviour/state.

Use existing serial lane_job.py for all heavy jobs. Record actual RED before
production edits, GREEN/refactor and remaining checks. The independent reviewer
completes a real role journey in Chrome; a source scan or contact sheet cannot
establish whole-app quality. Return scoped PASS/CHANGES REQUIRED/BLOCKED with
evidence. Save a compact resume handoff rather than repeatedly reading old chat.
