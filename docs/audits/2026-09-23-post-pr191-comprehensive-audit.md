## 4. Critical and High findings

**F01 — High; confidence High (vulnerable version), Medium (exploitability on this deployment); blocks Pilot/Production.** `package.json:54`, `pnpm-lock.yaml:3161,6841`, `next.config.ts:3-8`, `middleware.ts:154-157`. The resolved Next version is 15.5.23; the production dependency audit flags GHSA-2xp9-vwfh-vxw4 (AVIF optimizer RCE; fixed in 15.5.24). Next's `/_next/image` path bypasses this middleware's matcher, and no `images` override is configured. An externally reachable optimizer may therefore expose the vulnerable path. Correct by pinning a patched compatible Next release and rebuilding an image; verify dependency audit, real `/_next/image` reachability/AVIF handling and full CI before deployment. The *other* critical advisory, GHSA-p293-qw3h-jr36, is Windows-host-specific and does not establish an exploitable Linux container RCE. Do not conflate advisory count with two confirmed exploits.

**F02 — High; confidence High; blocks Pilot/Production.** `docker-compose.dokploy.yml:108-125`, `lib/jobs/audit-checkpoint-job.ts:53-60,78-82`, `worker/index.ts:77-80`, `docs/deployment.md:129-150`. The Dev worker schedules `audit.checkpoint` and `activity.export`, but Compose supplies neither `AUDIT_CHECKPOINT_SECRET` nor `R2_*`. The checkpoint calls `requireCheckpointSecret()` and `getObjectStore()` before processing; jobs will fail/retry rather than anchor externally. The same Compose file supplies no runnable backup service/scheduler; `Dockerfile:41-50` omits `scripts/`, and the live R2 upload test in `tests/db/db-backup.test.ts:72` is skipped without credentials. A local pg_dump/dry-run is not an offsite backup. Correct with an explicit, tested backup owner/schedule and service env for enabled jobs (or deliberately unschedule them), then verify real R2 upload, retention, job success and restore to a disposable DB before storing pilot money. **Dev rehearsal** can proceed without claiming backup readiness, but Dev handling of real pilot data cannot.

**F03 — High; confidence High for behaviour, Medium for consent-policy impact; blocks Pilot.** `lib/services/member-import.ts:88-98,209-230`, `lib/services/member-import-csv.ts:14-19,249-258`, `tests/member-import.test.ts` (import consent assertions). Import requires only guardian name and phone for minors, then unconditionally inserts `processing` consent with `{channel:"import"}`. The CSV has no consent-granted/evidence field and the guardian is never contacted or verified by this flow. The resulting consent row can be mistaken for guardian authorization despite only recording operator submission. Set a product/legal rule for legacy consent evidence: separately represent unverified imported data, or require and preserve affirmative guardian proof before granting consent. Verify minor/adult cases, missing/withdrawn consent, source evidence and access restrictions end to end. This is a **confirmed implementation behaviour** and a **policy risk**, not a legal conclusion.

**F04 — High; confidence Medium; blocks Pilot.** `lib/services/member-import.ts:123-190,193-245,247-263`, `lib/actions/member-import.ts:18-23,52-68`. A 2 MB string limit exists, but no row-count limit, import-id/lock or batch transaction does. For each row, duplicate lookup, code allocation and `createMember` run in separate transactions; the final import summary audit runs in yet another transaction. Simultaneous imports can race before either sees the other's rows, and a mid-file failure leaves already-created members/consents; the summary audit can itself fail after rows commit. No concurrent-import regression test was found in `tests/member-import.test.ts`. Correct with a bounded row budget and a deliberate per-import idempotency/transaction strategy or a clearly auditable resumable per-row protocol; verify two concurrent identical uploads, retry after interruption, generated and supplied code collisions, per-row audit and partial-error export. Ordinary sequential retry is tested and passes; this finding does not claim that sequential retry duplicates every row.

## 5. Medium and Low findings

**F05 — Medium; confidence High; blocks Production, Pilot if docs are used operationally.** `docs/deployment.md:172-175,210-212,270-280,885-902,1015-1022`, `docker-compose.prod.yml:58-76`, `docker-compose.dokploy.yml:53-77`. **F06 — Medium; confidence High; blocks Production.** `.github/workflows/deploy-prod.yml:70-86`, `.github/workflows/deploy-dev.yml:67-84`, `docker-compose.prod.yml:58-77,102-105`, `docs/pilot-release-checklist.md:491-503`. Even if an untracked VPS script supplies an override, source cannot establish that it runs the verified immutable image or avoids host exposure. Keep Production blocked; converge on a tracked, reviewed deploy unit/immutable image digest and verify rendered VPS config plus actual image IDs **with human/VPS access** before dispatch. Do not infer Dev Dokploy Compose also fixes the old Production SSH path.

**F07 — Medium; confidence High; blocks Pilot if link loss/theft is in the pilot threat model.** `lib/services/parent-link.ts:17-21,75-99,102-154`, `app/p/[token]/route.ts` and `app/p/[token]/receipt/[paymentId]/route.ts`. Parent tokens live seven days and use a sound HMAC signature, but the `jti` is not looked up against a revocation store. Once a link is leaked, staff cannot revoke that individual child's attendance and financial view without rotating the shared signing key and invalidating all parents' links. Add per-link revocation or per-person issuance epoch if the pilot expects immediate unlinking; verify old-link rejection, other guardians' links surviving, expiration and receipt denial. This is a **known deliberately accepted MVP design**, not a forgery vulnerability; `Math.random()` in the signed `jti` does not expose the HMAC secret.

**F08 — Medium; confidence High; Post-pilot (or Pilot if large imports).** `lib/services/member-import-csv.ts:48-105,165-199,269-282`, `lib/actions/member-import.ts:18-23`. The parser accepts unterminated quotes without error, treats quotes in unquoted fields as delimiters, and materializes all rows plus per-row service calls under only a character-count ceiling. A malformed CSV may silently merge lines into one record; 2 MB of tiny rows can produce a large query fan-out. Error CSV quotes commas/newlines but does not neutralize spreadsheet formula prefixes in untrusted fields if future errors echo cell contents at column start. Add explicit malformed encoding/CSV and row-budget tests; measure parse/preview/commit time and DB pool load at the actual limit. The current error columns start with numeric row, fixed field, and fixed-text reasons, so **current formula injection is not confirmed**.

**F09 — Low; confidence High; Post-pilot.** `scripts/check-line-count.ts` (soft/hard advisory gate), `db/preset-engine.ts:1-929`, `lib/services/staff-invitations.ts:1-607`, `app/p/[token]/route.ts:1-505`, `AGENTS.md:77-87`. The scanner prints 25 hard-limit violations while exiting 0; the largest product module is 929 lines. This is maintenance and review-surface debt rather than a proven runtime failure. Split by existing responsibility boundaries when touching those modules, then make the configured hard limit enforceable; verify behaviour and scanner exit on a known over-limit fixture.
