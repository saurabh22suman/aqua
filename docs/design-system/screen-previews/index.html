Aqua screen previews

Wireframes of the screens specified in docs/design-system/screens.md. They show composition, order and proportion — the block that dominates, what is a row, what is a sheet, where the scroll is. They are not final styling, and they are not evidence that a screen has been implemented.

Every block is labelled instead of filled with a value. A preview never invents a count, an amount, a trend or a percentage, and it never borrows an avatar, a gradient or a chart label from the reference boards. The mobile frames are 390 px and the desktop frames are 1280 px — the real contract viewports.

Owner Home

/owner

Owner and administrator only. The accountant is redirected to the fees screen. Gate: dashboard.view. One dominant action. At most three attention rows.

Callouts

1Identity header
Academy mark and name, the scoped location, the full date, the account control. The record search stays in the shell, never duplicated in the page.
2One dominant action
Collect payment, only with payments.record, and it lands on the dues list where an invoice can actually be settled. Add member and capture enquiry are quiet links.
3Summary tiles
Four, never five. Each label states its basis, each hint says what is included, each drill-down keeps the facility and period. Unavailable is a dash with the reason, never a zero.
4Attention queue
At most three rows. Each row states what, why now (the age) and where to act. No "View all" unless a real list exists. An empty queue is one quiet sentence.
5Today
Register state is completion — "12 of 12 marked" — and is never called attendance. Occupancy over capacity is its own late-toned warning.
6Chart band
One wide metric panel and one payment-mix panel. Both have a keyboard-reachable data table. Below the desktop breakpoint the same figures render as an accessible table, so a phone never downloads the chart engine.
7Quick links
The phone access path for the desktop-only destinations. Never a fifth bottom-navigation item.
8Shell
Viewport-bound sidebar, sticky top bar, content capped at 1280px, one vertical scroll owner.

States

·Quiet day
The day names the next class with coach, date, time and occupancy. Never an empty block.
·New academy
The onboarding hint appears only when no checklist step is complete.
·Chart unavailable
The chart band degrades to a stated panel; the rest of the page is unaffected.
·Keyboard
Search first, then tiles, rows and the data table. Focus is never hidden by the sticky top bar.
·Offline
No offline writes here. A failed read keeps the shell and names the block that failed.

Owner Members

/owner/members

The long page. Gate: members.read; changing a record needs members.write. Filters and search are URL state.

Callouts

1Search
First focusable control. Filters as the person types and is URL state, so Back restores the previous filter set and a shared link opens the same view.
2Add member
A quiet action above the list. It is absent when the role holds no members.write.
3Divided list
A long working list is one container with dividers, never a card per row. On a phone the row is two lines: identity and status first, supporting metadata second.
4Empty state
Name the state, say what is true, offer the verb that changes it. An empty block with no words is a bug.
5Working table
Aligned columns, money right-aligned, stable row height, the identity column is the destination.

States

·No results
One sentence plus the verb, describing the filtered set rather than the whole academy.
·Loading
Skeletons that match the row geometry, so the layout does not shift when the rows arrive.
·Error
The list stays, the failure names itself, the search text is kept and the retry sits beside the failure.
·Keyboard
Tab reaches every row; Enter opens the record. A long name truncates; an amount never collides with a status pill.

Owner Fees and payments

/owner/fees

Gate: reports.financial. Inside: invoices.read, invoices.write, payments.record, payments.read, payments.refund; voiding needs settings.manage. Money is exact paise here.

Callouts

1Tabs
URL state, so a shared link opens the same view. The drill-down from Home arrives here with the facility and period preserved.
2Rows
Two lines on a phone. Exact paise, right-aligned, tabular figures. A voided invoice stays readable and is struck through.
3Record a payment
A full page, not a sheet. The control is absent — not disabled and broken — when the role holds no payments.record.
4Pinned summary
The invoice being settled stays visible while the amount is entered, so nobody records against the wrong invoice.
5Save
One dominant action. Disabled while the save is in flight, re-enabled on failure with every entered value still in place.

States and recovery

·Empty
"Nothing due right now" is a real statement. A figure that could not be read is a dash with the reason, never a zero.
·Reversal
Ledger-only and stated beside the total. It is never netted into the collected figure.
·Offline
Money never goes offline. The save is refused with a plain "needs a connection" message, and a partial save says "check before retrying".
·Keyboard
The tab strip is a tablist with arrow-key movement; the amount field is 16px and right-aligned; focus moves to the first invalid field.

Owner Settings

/owner/settings

Gate: settings.manage. Six categories, each with a one-line summary. Opening a category shows only that category's destinations.

Callouts

1Orientation
One line, not a paragraph. The category summary carries the detail.
2Setup row
Only while the checklist is unfinished. It is not a standing nag for one unfinished item.
3Categories
Six, in the order an owner thinks in. Each row is 56px with an icon, a label, a summary and a chevron. A category the academy does not use — the skill ladder — is not offered.
4Appearance
The personal Appearance and motion preference live in the account block, not as an academy category. It is a personal preference, never tenant branding, and it never leaks between accounts on a shared device.
5Account
Identity and sign-out. A role without settings.manage has no Settings destination at all, so the shell carries a sign-out instead — the session must always be endable.

States

·Category open
The hub is replaced by that category's destinations, with a back link that keeps focus.
·Single site
The location destination stays singular in its wording until a second location exists.
·Failed save
The entered value and the field focus survive; the failure sits beside the field.

Coach Today

/coach

Gate: attendance.read; marking needs attendance.mark. Mobile only. One dominant element: today's sessions.

Callouts

1Heading
One line. The week belongs to the schedule tab and the roster to the members tab; Today is for acting now.
2Session card
Time, batch, enrolled and marked counts, and the lane strip. The strip colour carries meaning: normal, under-filled, or a problem.
3Under-filled strip
Amber when under-filled. The state is also written in words — colour is never the only carrier.
4Up next
Offer "Open register" only when the next session is today or tomorrow; further out, offer the schedule. Nothing today and nothing this week is one quiet sentence, not an empty block.

States

·No one enrolled
The card says "No one enrolled" rather than showing a zero over zero.
·Keyboard
Cards are links, reachable by Tab and activated by Enter.
·Recovery
A failed load keeps the Today framing and offers a retry beside it.

Coach Register

/coach/register/[sessionId]

Gate: attendance.read, marking attendance.mark. The approved offline queue applies here and nowhere else for student attendance.

Callouts

1Back link
A real link with a 44px target. The register is used mid-session, one-handed, in sunlight.
2Offline banner
Only when the approved queue is enabled for this identity. It never appears for a role whose tenant has the queue off — that state says it cannot save offline and refuses the write.
3Register rows
One tap to mark. The state is a word, not colour alone, and the row is a real control with an accessible name.
4Sync state
"offline — saved on device", "syncing N…" or "offline — can't save". A failed sync states how many marks could not be sent and keeps them.

Security and recovery

·Identity
The offline identity is scoped, expires and is purged on logout. An expired or revoked identity stops working offline and says so.
·Logout
Unsynced marks are never silently discarded: the count is stated before the sign-out completes.
·Failed mark
The register stays open and names the swimmer whose mark failed. The mark is not silently dropped.
·Session not found
"Session not found" with a way back to Today, using the tenant's own vocabulary for the word.

Reception Today

/reception

Gate: the surface itself. Each task row is hidden unless its permission and entitlement are both present — the list never offers a tap that would be refused.

Callouts

1Heading
The session count beside it, so the desk knows the day before it starts.
2Collect payment
The dominant task. Present with payments.record and the billing entitlement; absent — not greyed — when either is missing.
3Close day
Present with the same grant as collection. The close itself refuses an over-threshold count and names the limit.
4Check-in panel
Degrades to read-only for a role without attendance.mark rather than offering a tap that would fail.
5Staff board
Absent for a role without staff.attendance. A receptionist never sees staff pay.

States and recovery

·Quiet day
No sessions — say so in words and name what is available.
·Offline
Only the approved attendance queue may work offline, under the same identity, expiry and entitlement rules as the coach register. Money never does.
·Entitlement off
The row is absent, and the reason is not guessed at.

Reception Collect payment

/reception/collect-payment

Gate: payments.record plus the billing entitlement. Two steps of one task on a phone: show the QR, record the payment.

Callouts

1Purpose
One line. No tutorial.
2QR
If no payment QR is active, the block says so and points at the owner's settings. It never shows a broken or empty QR.
3Invoice
The invoice being settled is visible while the amount is entered, so nothing is recorded against the wrong invoice.
4Amount and method
The amount field is 16px and numeric; the method is a real radio group with a visible focus ring.
5Confirmation
States the invoice, the method and the amount. It appears only after the server has recorded the payment.

States and recovery

·No active QR
A named reason and a route to the owner, not an empty frame.
·Failed save
The entered amount and method survive and the save is re-enabled.
·Offline
Refused with a plain "needs a connection" message. Money is never optimistically recorded.
·Partly applied
The message says "check before retrying" rather than inviting a second submit.

Parent token page

/p/[token]

A signed link, no account and no session. Server-rendered markup with zero client JavaScript, served no-store, no-referrer and noindex. It never enters a cache, a manifest shortcut or an install prompt.

Callouts

1Academy identity
The tenant's own branding and vocabulary. No theme script reaches this page, so it never renders a theme and a shared device cannot leak a prior account's appearance.
2One child
The token names one person. Nothing on this page mixes children.
3Next session
Date, time, batch, coach and venue — the venue is omitted, not invented, when the session has no location.
4This month
Attendance percentage with the count beneath it, plus the recent list. Unmarked attendance is unknown, not zero.
5Fees
Read-only and exact. A receipt link opens the token-scoped receipt, which stays on the same contract.
6Contact
The academy is named rather than a phone number that may not exist.

Security states

·Invalid token
One generic "This link is no longer valid" page, identical to the page shown when the member no longer exists — a probing caller learns nothing either way.
·Footer
States that the link is unique to the child, expires in seven days and carries no tracking.
·Verification
The production artifact, not a dev server: the zero-JavaScript end-to-end check plus the response headers.

Ops Overview

/ops

Desktop-first at 1280×900 on the platform host, with its own session scheme. The needs-attention queue is the primary element; the KPI strip is context.

Callouts

1Attention queue
The primary element, not the KPI strip. Each row states the tenant, what is wrong, how old it is and a severity badge.
2Quick actions
Where the operator goes next. The WhatsApp entry appears only while the mock provider is enabled.
3Recent activity
A read of the platform activity log, with a link to the full log.

States and rules

·No snapshot yet
The metrics job runs nightly. Until it has run once the page says so rather than showing zeros.
·Empty queue
One quiet sentence: nothing needs attention.
·Viewer
A read-only operator sees no write controls. The server refuses the writes anyway — hiding the control is supplementary, never the enforcement.
·Audit
Every operator mutation writes its audit row in the same transaction as the change.
·Paid services
The messaging console is a mock in this phase. No paid provider is activated to satisfy a screen.
