The three reusable patterns

  • Working list/table — Members directory, Fees dues, transactions and invoices. Aligned columns, identity first, status and amounts scannable.
  • Bounded editor — Add swimmer and Edit member: labelled fields, grouped sections, validation near the control, explicit Cancel/primary.
  • Evidence with contextual action — an expanded invoice keeps lines, payments and the record-payment/reversal/void controls together; the member Overview pairs evidence with its next action.

Reading the preview

  • Desktop 1280×900; mobile 390×844. The bar above is preview chrome, not product UI — hide it before judging composition.
  • State switcher: populated, empty, loading, failed read, permission-limited, validation error, destructive confirmation (page-dependent).
  • Buttons that would mutate data show an explicit “preview only” note. Nothing is persisted.
  • Avatars, icons and fonts come from the app's installed packages; values are synthetic.

Run it

pnpm preview:owner-ui then open http://127.0.0.1:3210. The server is a small Node script (scripts/preview-owner-ui.ts); it reads only files in docs/design/owner-ui-preview/ and the installed font/icon/avatar packages.
