should say so.

A) RULES VS THEIR OWN EXAMPLES
------------------------------

A1. Audit columns ("without exception", §8.1) vs DDL omitting them.
    RECOMMENDATION: fix the examples, keep the rule absolute. The DoD
    requires every mutation audited with actor attribution, and F-15 wants
    a mechanical coverage test — both need updated_by to exist uniformly.
    Carve-outs belong in an explicit exemption list in §8.1, not silent
    omission. Proposed initial exemption list: audit_log
    (self-referential), webhook_events (provider-owned payloads), platform
    tables (plans, features, permissions, presets). Existing exemplar
    tables get their columns through their own build tasks (persons
    already does).

A2. "UUID v7 without exception" vs audit_log bigserial.
    Likely deliberate. RECOMMENDATION: amend the rule with a stated
    carve-out — append-only tables that are partitioned by time and never
    targeted by foreign keys may use bigserial; name audit_log as the sole
    current instance. Sequential IDs suit append-only hot-partition
    inserts, and nothing references an audit row by id. The defect was
    silence, not the choice.

A3. "Every index begins with tenant_id" vs unique constraints like
    (session_id, member_id).
    RECOMMENDATION: fix the examples. tenant_id is functionally dependent
    on session_id here, so leading with it is semantically free and
    preserves the locality/partition-readiness invariant — rewrite as
    (tenant_id, session_id, member_id) etc. for enrolments, sessions,
    attendance, shifts, staff_attendance, guardianships. Document one
    sanctioned exemption class: GiST exclusion constraints (bookings),
    where prepending tenant_id adds nothing. These constraint changes land
    inside existing tasks' migrations (C-18/C-19/C-22/V-23/V-24) — no new
    work, just corrected specs before those tasks execute.

A4. DESIGN.md "multiples of 4px only" vs mb-1.5 / px-2.5 / py-3.5.
    RECOMMENDATION: amend the rule. The snippets encode shipped visual
    intent validated against real screens; retro-fitting them to a strict
    4-grid changes spacing nobody asked to change. Proposed wording:
    "Base-4 grid. Half-steps (×2px) permitted below 16px for micro-spacing
    only." Makes the three snippets conforming, keeps the rule reviewable,
    stays honest about how Tailwind is actually used.

B7. AUDIT_LOG NULLABLE TENANT_ID — RECOMMENDATION: give it its own policy,
    do NOT allowlist it.

    Policy: strict tenant_id = current_setting('app.tenant_id',
    true)::uuid — NULL rows (platform-level actions) are invisible to
    tenant-scoped requests; platform reads go through the privileged role,
    as they already must.

    Consequence either way:
    - Own policy (recommended): F-08a's catch-all passes naturally with no
      special case; tenants can read their own audit trail (including the
      pay-read audits V-33 depends on) without any second code path;
      platform-action rows stay invisible to tenants by construction.
    - Allowlist: one less policy, but the most sensitive table in the
      system — it logs who looked at coach salaries — becomes readable by
      any future unscoped query path, and the catch-all gate permanently
      carries an exception someone must remember to justify. Rejected.
